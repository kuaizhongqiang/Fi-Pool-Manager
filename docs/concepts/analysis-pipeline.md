# 个股分析流水线

> 阶段：概念设计 — 单只股票从数据到最终报告的流程。
> 待细化：多角色分析的具体环节。

## 流水线流程

### 1. 数据获取

1.1 明确股票代码
1.2 从腾讯财经接口获取该股昨日行情数据
1.3 获取前 60 个交易日数据进行客观处理（计算技术指标、信号检测等）

### 2. 客观报告

本地 LLM 根据以下信息生成一份客观数据报告：
- 当前的技术指标与信号数据（第 1 步产出）
- 前 3 个交易日的客观报告（用于保持分析的连续性）

产出：一份客观的、数据驱动的分析报告。

### 3. 多角色分析

3.1 **舆情获取** — 通过搜索/舆情 API 获取该股最新舆情，生成舆情报告
3.2 **多角色分析** — 按固定顺序依次发言，每个角色有字数限制（适配本地 LLM 上下文窗口）
3.3 **最终报告** — 本地 LLM 综合以下三份材料，生成最终报告：
   - 客观报告（第 2 步产出）
   - 舆情报告（第 3.1 步产出）
   - 多角色分析结果（第 3.2 步产出）

### 4. 结束

## 多角色分析细化

### 角色与发言顺序

| 顺序 | 角色 | 分析重心 |
|------|------|---------|
| 1 | 技术分析师 | 走势形态、量价关系、技术指标信号 |
| 2 | 基本面分析师 | 估值水平、财务健康度、行业地位 |
| 3 | 舆情分析师 | 市场情绪、消息面、新闻舆情 |
| 4 | 风控官 | 下行风险、流动性问题、利空因素 |

### 轮次设计

- **第一轮**（必须）：按 1→2→3→4 顺序依次发言。每人只陈述自己视角的观点，不回应他人。
- **第二轮**（可选）：如第一轮中出现分歧点，可发起第二轮回应。按 4→3→2→1 顺序，每人可以回应前面对手的观点。

### 上下文约束

- 本地 LLM（LM Studio）上下文窗口有限
- **每个角色的单次发言设定字数上限**（具体数值待技术选型后确定）
- 每轮开始时，将本轮所有历史发言拼接后发给下一个角色，保证每个角色能看到前面的讨论
- 若历史累积过长，前面的发言可能需要压缩或截断

### 最终综合

多角色讨论结束后，LLM 综合以下三份材料生成 FinalReport：
- 客观报告（第 2 步产出）
- 舆情报告（第 3.1 步产出）
- 多角色讨论记录（多轮发言的完整内容）
